## What_Happens_Internally

Timer registers callback in **Dart** Event Loop. After duration:

- Callback is pushed into event queue
- Event loop executes it
- UI thread remains non-blocking

That’s why **Flutter** doesn’t freeze.

---
## Timer

Timer comes from:

```dart
import 'dart:async';
```

It schedules code to run in the future. There are two types:

- **A) One-shot Timer:**

  Runs once after a delay.

  ```dart
  Timer(Duration(seconds: 2), () {
    print("Runs after 2 seconds");
  });
  ```

- **B) Periodic Timer:**

  Runs repeatedly at fixed intervals.

  ```dart
  Timer.periodic(Duration(seconds: 1), (timer) {
    print("Runs every 1 second");
  });
  ```

## Debounce

Debounce means: “Wait until the user stops doing something before running a task.” Example:

- User types in search field
- Instead of calling API every keystroke
- We wait 500ms after they stop typing
- Then call API once

It prevents:

- Unnecessary database writes
- Too many API calls
- Performance issues

Think of it like this, user toggles checkbox quickly:

```text
Tap Tap Tap Tap Tap
```

Without debounce:

```text
DB update DB update DB update DB update DB update
```

With debounce:

```text
(wait 500ms)
DB update only once
```

That’s the idea.

## Database/API_Debounce

For DB or API Debounce use one-shot timer `Timer((…), () {})` that runs once after a delay. If user taps multiple times instead of updating DB or calling API multiple times, we use debounce (wait until user is done then do it)

Instead of calling API every keystroke or user tap. We wait 500ms after they stop typing. Then call API or update DB once

First create an object (`_debounce`) of Timer class which can be nullable

Then initialize it in the method we are updating data in the List to save in the database

Make sure to cancel any previous debounce if any was running (this resets the debounce to 500 milliseconds every time user taps) using `.cancel()` method. This is the heart of debounce. We are basically saying: “Forget the previous delayed call. Start fresh.” Now only the LAST user action survives.

Then before database update or write we are using debounce. `Timer(…)` takes a `Duration(…)` to run the code or logic after that specified time or delay (like after 500 milliseconds do this)

In `Timer(…)`, the second parameter is a callback method that takes a lambda function `(){}` and the code written here like database update happens after the delay

```dart
Timer? _debounce;

void checkBoxChanged(bool? value, int index) {
  setState(() {
    db.toDoList[index][1] = value;
  });
  
  // Cancel previous timer
  _debounce?.cancel();
  
  // Start new timer
  _debounce = Timer(const Duration(milliseconds: 500), () {
    db.updateData();
  });
}
```

## OTP_Timer_or_Periodic_Timer

For OTP timer or to set any timer we use periodic timer `Timer.periodic((…), (timer){…})` that runs repeatedly at fixed intervals

This means, every 1 second, run this callback (second parameter of `Timer()`).

What’s happening logically:

- Every second → decrease time
- When reaches 0 → stop timer
- Show button again

This is CORRECT usage of periodic timer.

First create an object(`_resendOTPTimer`) of `Timer(…)` class it can be late or nullable

Then we assign it using `Timer.periodic(…)`. `Timer.periodic()` takes a `Duration(…)` as the first parameter which is the specified fixed interval after which the callback (the second parameter) runs. The callback gives us timer internally from **Flutter** so we can cancel it using `timer.cancel()`

We also define an integer (`_startTime`) for countdown (and UI display) which decreases at fixed interval when callback runs. If it reaches zero then stops timer

Very IMPOTANT, Make sure to `.cancel()` timer (`_resendOTPTimer`) in `dispose()` method. Because:

- Timer keeps running in background.
- If screen is destroyed and timer continues → memory leak.

Always cancel:

- Timers
- Streams
- Controllers

If we don’t → our app becomes unstable.

When using **Provider** SM use helper methods like `stopTimer()` to cancel the timer. Don’t call the Provider `dispose()` method in UI (Worst Practice), Provider will automatically handle it but then we need to inject the **Provider** in that screen using `ChangeNotifierProvider.value(…)` not in the **`main.dart`**

```dart
int _startTime = 30;
bool _showResetOTPButton = true;
late Timer _resendOTPTimer;

int get startTime => _startTime;
bool get showResetOTPButton => _showResetOTPButton;

void startTimer () {
  _startTime = 30;
  
  _showResetOTPButton = false;
  
  _resendOTPTimer = Timer.periodic(const Duration(seconds: 1), (timer) {
    if (_startTime == 0) {
      timer.cancel();
      _showResetOTPButton = true;
    } else {
      _startTime--;
    }
    
    notifyListeners();
  });
}

void stopTimer(){
  _resendOTPTimer.cancel();
}

@override
void dispose() {
  _resendOTPTimer.cancel();
  super.dispose();
}
```

## Deep_Understanding,_Debounce_vs_Throttle

Most juniors confuse these.

**Debounce** → Wait until user stops. Example:

Typing search.

**Throttle** → Allow action only once every X time. Example:

Prevent double click on login button.

Different behavior.

## Clean_Debounce_Utility(Professional_Pattern)

Instead of manually writing timer everywhere, create reusable class / service

Now our code is clean and scalable. This is how experienced developers write it. Or we can write this logic directly in the **Provider**, **GetX** state management controller class.

```dart
class Debouncer {
  Debouncer({required this.delay});
  
  final Duration delay;
  Timer? _timer;
  
  void run(VoidCallback action) {
    _timer?.cancel();
    _timer = Timer(delay, action);
  }
  
  void dispose() {
    _timer?.cancel();
  }
}
```

Usage:

```dart
final _debouncer = Debouncer(delay: Duration(milliseconds: 500));

void checkBoxChanged(bool? value, int index) {
  setState(() {
    db.toDoList[index][1] = value;
  });
  
  _debouncer.run(() {
    db.updateData();
  });
}
```

## Final_Mental_Model

Think like this:

| Feature                | Purpose          | Use Case          |
| ---------------------- | ---------------- | ----------------- |
| **`Timer()`**          | Run code later   | Delay execution   |
| **`Timer.periodic()`** | Run repeatedly   | Countdown         |
| Debounce               | Wait for silence | Search, DB update |
| Throttle               | Limit frequency  | Button spam       |

## Riverpod_Debounce

For **Riverpod**, async notifier, here:

- **`isAutoDispose:`** automatically disposes when screen leaves. Professional habit.
- `state = AsyncLoading()` **Riverpod** async state has 3 states: Loading, Data and Error. We manually control them.
- `_debounce?.cancel()` real debounce logic.

**`AsyncNotifier<T>`** class:

```dart
class SearchNotifier extends AutoDisposeAsyncNotifier<List<String>> {
  Timer? _debounce;

  @override
  Future<List<String>> build() async {
    ref.onDispose(() {
      _debounce?.cancel();
    });

    return [];
  }

  void search(String query) {
    // Cancel the previous timer
    _debounce?.cancel();

    // Optional: clear results for empty query
    if (query.trim().isEmpty) {
      state = const AsyncData([]);
      return;
    }

    // Start a new debounce timer
    _debounce = Timer(
      const Duration(milliseconds: 500),
      () async {
        state = const AsyncLoading();

        try {
          final results = await searchApi(query);

          state = AsyncData(results);
        } catch (e, st) {
          state = AsyncError(e, st);
        }
      },
    );
  }
}

final searchProvider =
  AsyncNotifierProvider.autoDispose<SearchNotifier, List<String>>(
    SearchNotifier.new,
);

```

UI layer:

```dart
class SearchScreen extends ConsumerWidget {
  const SearchScreen({super.key});
  
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final searchState = ref.watch(searchProvider);
    
    return Scaffold(
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(16),
            child: TextField(
              onChanged: (value) {
                ref.read(searchProvider.notifier).search(value);
              },
            // …
          ),
          Expanded(
            child: searchState.when(
              loading: () =>
                  const Center(child: CircularProgressIndicator()),

              data: (results) {
                if (results.isEmpty) {
                  return const Center(child: Text("No Results"));
                }
                return ListView.builder(
                  itemCount: results.length,
                  itemBuilder: (context, index) {
                    return ListTile(
                      title: Text(results[index]),
                 // …
}
```

Internal flow for this:

```text
User types →
search() called →
Timer waits 500ms →
If user types again → previous timer cancelled →
After 500ms idle → API called →
state updated →
UI rebuilds automatically
```

This is production level debounce. **Riverpod** Notifier keeps Business logic separated, UI clean, AutoDispose handles memory and Testable

## RxDart_Debounce

True Reactive Debounce (RxDart Style). If we want real stream operator. Add:

```yaml
dependencies:
  rxdart: ^0.27.7
```

Then:

```dart
import 'package:rxdart/rxdart.dart';
final _queryController = PublishSubject<String>();
_queryController
    .debounceTime(const Duration(milliseconds: 500))
    .listen((query) {
      // call API here
    });
```

That’s using **RxDart** operator. But for most **Flutter** apps, **Riverpod** + Timer is enough.
