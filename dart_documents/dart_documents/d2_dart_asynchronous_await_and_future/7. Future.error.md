In **Dart**, **`Future.error(…)`** creates a **`Future`** that immediately completes with an error instead of a value. Think of it as the opposite of **`Future.value(‘Success’)`**

Mental Model (IMPORTANT). A **`Future`** has only 3 states:

- ⏳ Pending (**`Future.loading()`**)
- ✅ Completed with value (**`Future.value()`**)
- ❌ Completed with error (**`Future.error()`**)

**`Future.error()`** directly jumps to state error

---
## Basic_Example

**`Future.error()`** behaves like throwing an error inside async code. We use it for simulating API failures.

```dart
Future<String> getData() async {
  return Future.error('Something went wrong');
}
// Usage
try {
  final data = await getData();
  print(data);
} catch (e) {
  print(e); // ✅ catches the error
}
```

---
## Difference_with_throw_Exception

**`throw`** is used inside async functions and synchronous style error

**`Future.error()`** explicitly creates a failed future and works even outside async

**`Future.error`** = manual future failure and **`throw`** = language-level exception

```dart
Future<String> test() async {
  throw 'Error';
}
Future<String> test() {
  return Future.error('Error');
}
```

## Real_Flutter_Use_Case

API failure simulation.

```dart
Future<String> fetchUser() {
  bool hasError = true;
  if (hasError) {
    return Future.error('API failed');
  }
  return Future.value('User Data');
}
```

## Use_Cases

Case-1, Repository Layer (Clean Architecture)

```dart
Future<User> getUser() {
  if (networkFail) {
    return Future.error(Exception('No internet'));
  }
  return api.getUser();
}
```

Case-2, Form validation with async

```dart
Future<void> submit() {
  if (email.isEmpty) {
    return Future.error('Email required');
  }
  return Future.value();
}
```

Case-3, Testing (VERY COMMON)

```dart
when(mockRepo.getUser())
    .thenAnswer((_) => Future.error('Failed'));
```
