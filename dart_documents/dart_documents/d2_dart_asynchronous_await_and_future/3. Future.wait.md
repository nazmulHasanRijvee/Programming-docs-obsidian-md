**`Future.wait()`** runs multiple futures (asynchronous) in parallel and waits for all of them to complete. It completes only when every **`Future<T>`** in the List finishes or fails if any one throws an error.

Here’s what happens:

- All three **`Future's`** start running at the same time.
- **Dart** waits until all are done before continuing.
- The `await` returns a list of results if the **`Future's`** return values.

```dart
await Future.wait<void>([
  fetchWeather(),
  getUserProfile(),
  loadSettings(),
]);
```

> **NOTE:** If we use **`Future.wait()`** in **`initState()`** we do not need to use **`await`** or use a helper **`async`**  function/method

---
## Use_Case

Its really useful when we are calling more than one **`Future<T>`** or **`async`** method and awaiting them using **`await`**.

Instead of writing one after another meaning after completing one **`Future`** starts another, we run all of them parallelly (Best Practice)

```dart
Future<void> _getData () async {
  await fetchWeather(), // runs first
  await getUserProfile(), // runs after the first one finishes
}
```

With **`Future.wait(…)`**

```dart
Future<void> _getData () async {
  await Future.wait<void>([
  fetchWeather(), // both runs parallelly at the same time
  getUserProfile(), // doesn’t wait for the first one
 ]);
}
```

But this pattern only works if our second **`Future<T>`** method is not dependent on the first one otherwise second **`Future<T>`** will run alongside the first one with no value and showing error

```dart
Future<void> _getData () async {
  final cityName = await fetchCity(),
  await getWeather(city: cityName),  // dependent on the first one, Future.wait(…) will cause error
}
```

## With_Return_Values

By default, **`Future.wait()`** expects to return a value or List of values or results of **`Future`**’s

Here, both **`async`**’s run parallelly and total wait time is 2 seconds not 3 seconds.

We can also get the values of a **`Future<T>`** function directly without using a global variable outside the function and set it in `setState`.

```dart
Future<String> fetchWeather() async {
  await Future.delayed(Duration(seconds: 2));
  return "☀️ Sunny";
}
Future<String> fetchTemperature() async {
  await Future.delayed(Duration(seconds: 1));
  return "27°C";
}
void main() async {
  final results = await Future.wait([
    fetchWeather(),
    fetchTemperature(),
  ]);
  print(results); // ["☀️ Sunny", "27°C"]
}
```

## With_no_return_values

In order to tell **Dart** that **`Future.wait()`** does not return a value just calls the functions parallelly we have to add **`<void>`** like this **`Future.wait<void>()`**. This pattern is perfect for **`initState()`** in **Flutter** apps. We can’t directly return from the **`Future`** function we have to use the global variable in this way.

```dart
Future<void> loadAppData() async {
  await Future.wait<void>([
    initializeDatabase(),
    preloadImages(),
    checkUserLogin(),
  ]);
  print("✅ All setup done!");
}
```
