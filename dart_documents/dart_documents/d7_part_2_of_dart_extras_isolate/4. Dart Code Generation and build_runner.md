Normally, we write **Dart** code → **Dart** compiler runs it. With code generation:

```text
We write some Dart code
       ↓
You add metadata/annotations (decorators)
       ↓
Code generator analyzes our code
       ↓
It writes more Dart code for us
       ↓
Our app compiles all of it
```

For example, imagine we have:

```dart
class User {
  User({
    required this.name,
    required this.age,
  });

  final String name;
  final int age;
}
```

We might want **`Map<String, dynamic> toJson()`** and **`User.fromJson(...)`** for JSON data serialization and deserialization. We could manually write those methods and constructors but imagine having 50 models. That's repetitive boilerplate.

A code generator can look at our model (**`User`**) and generate that code automatically.

---
## Dart’s_build_runner

**`build_runner`** is a package or tool. Important distinction, **`build_runner`** is not usually the thing that knows how to generate our code. It's the engine/runner in **Dart** that runs code generators called **Builders**

**`build_runner`** is the orchestrator where **`json_serializable`**, is a code generator/Builder, **`freezed`** is another generator, **`retrofit_generator`** is another generator and so on. A generator used by **`build_runner`** is called a Builder.

**`build_runner`** discovers Builders, gives them input then Builders generate files

Think:

```text
                 build_runner
                       │
          ┌────────────┼─────────────┐
          ↓            ↓             ↓
  json_serializable   Freezed      Retrofit
          ↓            ↓             ↓
      JSON code     Model code     API code
```

Codes are generated using this command:

```bash
dart run build_runner build
```
