**Flutter** runs our app on a Single main Thread (UI thread). This thread is responsible for:

- Rendering frames (60 FPS -> 16ms per frame)
- Handling gestures
- Running our **Dart** code

If we block it, like doing heavy computation (such as parsing large JSON data into objects)

```dart
void heavyTask() {
  for (int i = 0; i < 1e9; i++) {…}
}
…
onPressed: () {
  heavyTask();
}
```

As a result, UI freezes, Jank and ANR (Android Not Responding)

Solution, Isolates. **Dart** doesn’t use threads like **Java**. It uses Isolates. Think:

- Thread -> Shared memory
- Isolate -> Separate memory

Each isolate:

- Has its own memory
- Has its own event loop
- Cannot directly share variables

Use isolates for:

- JSON parsing (huge response)
- Image processing
- Encryption
- Sorting large lists

---
## Communication

Uses message passing for communicating with the main thread.

```dart
sendPort.send(data);
```

## Mental_Model

```text
UI Thread (Main Isolate)
       |
       |  (request)
       ↓
  New Isolate
  [Heavy Work]
       |
       |  (result)
       ↓
UI Thread updates UI
```

## Isolate.run_Basic_Syntax

This is the cleanest way to run background work.

First define a **`Future`** method (because work is async) for heavy computation.

Then return **`Isolate.run()`** method and **`await`** it. It creates a new isolate and runs our callback function inside it

Then whatever heavy CPU task written in that function runs OFF UI thread

Finally, result is returned back to main thread

```dart
Future<int> heavyCalculation() async {

  return await Isolate.run(() {
    int sum = 0;
    for (int i = 0; i < 100000000; i++) {
      sum += i;
    }
    return sum;
  });
  
}
```

---
## What_Happens_Internally

- Spawn isolate
- Copy required data
- Execute function
- Send result back
- Kill isolate

---
## Difference_with_Compute()

**`compute()`** is just a wrapper over isolates but simplified for **Flutter** UI usage.

Isolate.run() vs compute():

| Feature | compute() | Isolate.run() |
| --- | --- | --- |
| Flexibility | ❌ Limited | ✅ Full |
| Function type | Top-level only | Any closure |
| Arguments | One | Multiple (via closure) |
| Readability | Simple | Cleaner modern |
| Control | Low | Medium |
| Platform | Flutter only | Pure Dart |

## Difference_with_Isolate.spawn()_Manual_Way

This low-level control and we had to manage:

- Ports
- Lifecycle
- Data passing
- Cleanup

Old complex way:

```dart
void isolateEntry(SendPort sendPort) {
  int result = 0;
  for (int i = 0; i < 100000000; i++) {
    result += i;
  }
  sendPort.send(result);
}

final receivePort = ReceivePort();
await Isolate.spawn(isolateEntry, receivePort.sendPort);
final result = await receivePort.first;
```

---
## Use_Cases

Use **`Isolate.run()`** when:

- CPU-heavy task
- Need clean code
- Need closure access

Use **`compute()`** when:

- Simple transformation
- Quick Flutter helper
- Legacy code

Use **`Isolate.spawn()`** when:

- Long-running background service
- Streams / continuous work
- Custom isolate management

---
## Important_Pitfalls_VERY_IMPORTANT

Don’t use isolates for:

- Network calls (already async)
- Database queries (already async)

Isolates are for CPU-bound work, no I/O

Large data copy cost. Passing this to isolate = expensive copy

```dart
List bigList = List.generate(1e7, (i) => i);
```
