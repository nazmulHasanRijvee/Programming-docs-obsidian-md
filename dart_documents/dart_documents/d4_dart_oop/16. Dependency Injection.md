DI is a design pattern. Instead of creating dependencies inside classes, inject what they need. Benefits:

- Loose coupling
- Easy testing
- Cleaner architecture

Tools like **get_it** or **Riverpod** help for this. Without DI:

```dart
class UserRepository {
  final api = ApiService();

  Future<…> getUser() {
    return api.fetchUser();
  }
}
```

With manual DI, easier testing:

```dart
class UserRepository {
  UserRepository({required this.api});
  
  final ApiService api;
}

void main () {
  final api = ApiService();
  final repo = UserRepository(api: api);
  
  runApp(MyApp(repo));
}
```
