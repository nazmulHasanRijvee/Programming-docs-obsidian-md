An interface is just a contract it says any class that implements me must define these methods. It is like a rule that every class must follow meaning the methods must be defined according to the behavior of the class.

By using **`implements`** keyword, we can implement the interface class.

Overriding the abstract methods with our own implementation using **`@override`** annotation. Since we need to define those methods no matter what.

Creating object of the interface class using Polymorphism (SEE BELOW). Polymorphism allows our **`PaymentGateway`** class to point to different implemented class objects (**Bkash**, **Nagad**), and the correct overridden or implemented methods (**`cashIn()`**, **`cashout`**) is executed at runtime depending on the object type.

We use abstraction or interfaces to define a set of rules (methods or functions) that the child class must define or **`@override`**. For example, defining the cash out charge rate which is a must for any mobile banking like Bkash or Nagad.

```dart
abstract class PaymentGateway {  // add interface for MODERN
  void cashOut (double amount);
  void cashIn (double amount);
}

class Bkash implements PaymentGateway {
  @override
  void cashIn(double amount) {
    print("Cash out charge 20 taka per 1000 taka");
  }
  
  @override
  void cashOut(double amount) {
    print("Cash in free");
  }
}

class Nagad implements PaymentGateway {
  @override
  void cashIn(double amount) {
    print("Cash out charge 10 taka per 1000 taka");
  }
  
  @override
  void cashOut(double amount) {
    print("Cash in free");
  }
}

void main () {
  PaymentGateway payment1 = Bkash();
  payment1.cashIn(5000);
  payment1.cashOut(5000);
  
  PaymentGateway payment2 = Nagad();
  payment2.cashIn(10000);
  payment2.cashOut(8000);
}
```

> **NOTE:** There’s **`interface`** keyword for declaring interface abstraction classes in Modern way see dart part two of OOP.

## Interface_Class_Usage_Pattern

When an interface class (**`TokenSource`**) is implemented using **`implements`** keyword and another class like **`APIService`** takes the **`TokenSource`** as a parameter and if we a pass an **`AuthService`** class which implements **`TokenSource`** then only that part of the implemented part will be passed to the **`APIService`** not the whole **`AuthService`** (Really useful for dependency injection and can’t be done using **`extends`** cause that will pass the entire **`AuthService`** class).

```dart
abstract class TokenSource {
void doThat (…);
}

class AuthService implements TokenSource {
  @override
   void doThat(…) {…}
}

class APIService {
  APIService({required this.tokenSource});
  
  final TokenSource tokenSource;
}

// Usage
final apiService = APIService(AuthService());
```

> **NOTE:** It can be used for interchangeability too. For more info see d5 part two of dart OOP.
