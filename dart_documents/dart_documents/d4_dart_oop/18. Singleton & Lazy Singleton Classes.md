A Singleton means “Only ONE instance or object of this class exists in the entire app.”

A Singleton class creates only one object for the entire app. Key points:

- Saves memory and shared globally
- Common in services like:
  - **Dio** service, API service
  - Database service, Repository cache
  - Analytics service (**FirebaseAnalytics**)
  - App config (Environment manager)

Mental model:

```text
App Memory
   ↓
One ApiService object
   ↓
Everybody uses same reference
```

It can be created using two patterns like **`factory`** unnamed (or default) constructor.

```dart
class ApiService {
  ApiService._internal();
  
  static final ApiService _instance = ApiService._internal();
  
  factory ApiService() {
    return _instance;
  }
}
```

Or **`_privateConstructor()`** this prevents class calling for instance creation (**`ApiService()`** not allowed) so nobody can create new instances externally.

```dart
class ApiService {
  ApiService._privateConstructor();
  
  static final ApiService instance =
      ApiService._privateConstructor();
      
  void fetchData() {
    print("Fetching...");
  }
}
```

Lastly, Singleton is not a global variable or global state everywhere, it is a controlled shared instance and centralized lifecycle.

## Lazy_Singleton_Class

Singleton class instance is one shared object created immediately when class is first loaded.

While Lazy Singleton class instance is one shared object created only when needed.

This lazy creation saves memory and improves performance.

Null aware assignment (**`??=`**) ensures if null → create instance else → reuse existing instance or object.

```dart
class DatabaseService {
  DatabaseService._();

  static DatabaseService? _instance;

  static DatabaseService get instance {
    _instance ??= DatabaseService._();
    return _instance!;
  }
}
```

## Important_Info

1. **INFO-1**, In many languages Singleton thread safety is hard BUT in **Dart** single isolate execution simplifies this greatly and still relevant with isolates though.
2. **INFO-2**, Modern architecture often prefers Dependency Injection (passing as parameter in class constructor) instead of Manual Singleton access.
3. **INFO-3**, Overusing Singletons creates:
   - Hidden dependencies
   - Tight coupling
   - Hard testing
   - Global state mess
4. **INFO-4**, instead use **`get_it`** package or service locator for:
   - easier testing
   - swappable implementations
   - cleaner architecture
