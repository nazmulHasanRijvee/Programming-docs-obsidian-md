By using **`interface`** keyword after **`abstract`** keyword when defining interface classes we can prevent inheriting (**`extends`**) the interface class in another file or library (if used **`import`**). But we can inherit the interface class in the same file.

Instead of:

```dart
abstract class ApiClient {
  Future<void> getData();
}
```

If we do this, then **ApiClient** class can only be inherited (**`extends`**) in that same file. But in another file, it only can be implemented (**`implements`**) not inherited (Best practice, implement interface not inherit it).

Like properties of interface class shouldn’t be available in the implemented class (only methods that needs to be implemented) but if extended then properties or attributes will be available which makes interface abstraction pointless:

```dart
abstract interface class ApiClient {
  Future<void> getData();
}
// Same file
class ApiService extends ApiClient {
  @override
  Future<void> getData() async {
    // API call
  }
}
// In a different file, must implemented
class ApiService implements ApiClient {
  @override
  Future<void> getData() async {
    …
  }
}
```

So, this means:

- It cannot be instantiated (**`abstract`**).
- It is meant to be implemented (**`interface`**).
- It cannot be extended from outside the library.

Use it if we're writing a:

- Repository interface
- Service interface
- Or dependency injection contract (**`TokenSource`**)

**`abstract interface class`** is the modern recommendation. It better communicates the design intent and prevents accidental inheritance. It makes APIs clearer and more maintainable.
