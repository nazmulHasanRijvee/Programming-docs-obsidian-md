Encapsulation in **Dart** can be achieved by prefixing an identifier with an underscore (**`_`**). So, they can only be accessed in the same file or library-level.

But if we had to initialize a private property (**`_age`**) of a class through a named constructor parameter. Before we couldn't write **`Animal({required this._age})`**.

Instead, we had to use a normal parameter and manually assign it in the initializer list. The constructor parameter is public (**`age:`**), while the field remains private (**`_age`**).

```dart
class Animal {
  late final int _age;
  Animal({required int age}) : _age = age;
  ...
}
```

But Starting from **Dart 3.12+**, we can directly use a private field in a named initializing formal (**`age:`** for **`_age`**) at the call site, **Dart** automatically removes the leading underscore (_) from the parameter name (Reducing Boilerplate Code):

```dart
class Animal {
  late final int _age;
  Animal({required this._age});
  //...
}

void main () {
  final animal = Animal(age: 20); // age: auto generated
}
```

> **NOTE:** Positioned parameters are disallowed now for Private fields.
