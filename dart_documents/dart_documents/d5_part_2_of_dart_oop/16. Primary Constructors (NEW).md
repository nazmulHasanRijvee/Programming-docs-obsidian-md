Starting from **Dart 3.13+**, this is a “Syntactic Sugar” (better syntax) which is built on **Dart**’s OOP fundamental (normal constructors). It basically comes from **Kotlin**.

---
## Basic_Usage

In old **Dart**, we did this:

```dart
class Point {
  final int x;
  final int y;
  Point(this.x, this.y);
}
```

But starting from **Dart 3.13+**, we do the below which basically means put the constructor parameters in the class header (**class ClassName** …) instead of the class body **`{}`**. And **`final`**/**`var`** tells **Dart** to create fields from those parameters (we must add these SEE BELOW).

Also, if there’s nothing in the class body **`{}`** (like no methods or multiple parameters) then we can end it with semicolon (**`;`**) no curly braces needed **`{}`**.

```dart
class Point(
  final int x,
  final int y,
);
```

So **`class Point(final int x, final int y);`** conceptually gives us the same thing as above in Old **Dart**. The runtime behavior is the same, we’re just removing the boiler plate code. That's why it's particularly useful for:

- DTOs,
- Models
- Configuration classes
- Immutable state objects, etc.

---
## final_vs_var_in_Primary_Constructor_(IMPORTANT)

VERY IMPORTANT, we must add **`final`** (if it’ll be immutable in the class body) or **`var`** (if it’ll be mutable) before the data type (**`int x`**) for Primary Constructor declaration. So, this:

```dart
class User(
  final String name,
  var int age,
);
```

Becomes:

```dart
final String name;
int age;
```

So:

- **`final`** → creates a final instance field
- **`var`** → creates a mutable instance field
- no **`final`**/**`var`** → doesn't create a field, only used for constructor body

For example, **`class User(String name);`** here **name** is just a constructor parameter for the constructor body. It does not become **`this.name`** or **`user.name`**. Like:

```dart
class User (String name) {
  this {
    print("Name: $name");
  }
}
```

## Named_Parameters_Work_Normally

For example:

```dart
class FormatterOptions({
  final int indent = 0,
  required final int pageWidth,
}) {
  // ...
}
```

Simply becomes the primary-constructor equivalent of:

```dart
class FormatterOptions {
  final int indent;
  final int pageWidth;
  FormatterOptions({
    this.indent = 0,
    this.pageWidth = 80,
  });
}
```

So, we can still use named parameters (nothing new):

```dart
final options = FormatterOptions(indent: 2, pageWidth: 120);
```

## Primary_Constructors_Body

In old **Dart**, constructor body (for running additional code when instance is created):

```dart
class User {
  final String name;
  User ({required this.name}) {
    print("Name: $name");
    // Additional code …
  }
  …
}
```

In Primary Constructors body **`this`** keyword is used (**`this {}`**) like this:

```dart
class User ({required final String name}) {
  this {
    print("Name: $name");
    // Additional Code …
  }
  …
}
```

**`this {}`** runs when an object or instance of the class is created just like normal constructor body.

---
## Multiple_Constructors_or_Named_Constructors_in_Primary_Constructor

We can also have a named primary constructor (Multiple Constructors idea) like:

```dart
class Point.custom(
  final int x,
  final int y,
);
```

Which is equivalent to:

```dart
class Point {
  final int x;
  final int y;
  Point.custom(this.x, this.y);
}
```

Notice the difference, Unnamed Primary Constructor (default one) **`class Point(final int x, final int y);`** and Named Primary Constructor (multiple one) **`class Point.custom(final int x, final int y);`**.

## super_or_Inheritance_in_Primary_Constructor

Primary constructors alsso make inheritance cleaner. Old:

```dart
class Person {
  final String name;
  final int age;
  Person(this.name, this.age);
}

class Employee extends Person {
  final String role;
  Employee(
    String name,
    int age,
    this.role,
  ) : super(name, age);
}
```

New approach, this is where this syntax starts becoming genuinely nice in large Flutter models:

```dart
class Person(
  final String name,
  final int age,
);

class Employee(
  super.name,
  super.age,
  final String role,
) extends Person;
```
