It is essentially interface-based abstracting for interchangeability. Like exposing functionality through an interface (**`CacheService`**) while keeping the underlying implementation (**`SharedPreferences`**) replaceable (with other packages like **`Mocktail`** etc.).

```dart
abstract interface class CacheService {
  Future<void> save<T>(CacheKey key, T value);
  T? get<T>(CacheKey key);
  Future<void> remove(List<CacheKey> keys);
  Future<void> clear();
}

class SharedPreferencesService implements CacheService {
  SharedPreferencesService(this.prefs);
  final SharedPreferences prefs;

  @override
  Future<void> save<T>(CacheKey key, T value) async {
    // implementation
  }

  …
}
```

This implementation can then be easily swapped through the Provider (or **`get_it`**).

```dart
final cacheServiceProvider = Provider<CacheService>((ref) {
  final prefs = ref.watch(sharedPreferencesProvider);
  return SharedPreferencesService(prefs);
});
```

For testing, the concrete implementation can be replaced with a mock implementation using packages such as **`Mocktail`** and overriding the Provider with (**`.overrideWith()`** in Riverpod).

```dart
class MockCacheService extends Mock implements CacheService {}
…
```

This keeps the rest of the application dependent on the **`CacheService`** interface, rather than directly depending on **`SharedPreferences`**.

This pattern is highly used in Testing. There’s also **`get_it`** example of this too SEE f3 state management folders f6 get it service locator doc.
