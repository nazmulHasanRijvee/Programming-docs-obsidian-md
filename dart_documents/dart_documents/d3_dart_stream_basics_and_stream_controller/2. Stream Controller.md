**`StreamController`** decides when data is omitted. Think of it like a microphone where the controller adds data and listeners receive data.

---
## Basic_Syntax

Create a **`StreamController<T>`** using OOP. Then listen to the **Stream** using **`.stream`** property of the controller and **`.listen(…)`** method (which returns a **`StreamSubscription<T>`**)

Then add data to controller using **`.add()`** method.

> **IMPORTANT:** After listening to the **StreamController** dispose it using **`controller.close()`** method to prevent Memory Leak.

```dart
import 'dart:async';

void main() {
  final controller = StreamController<String>();
  controller.stream.listen((message) {
    print(message);
  });
  controller.add("Hello");
  controller.add("World");
  controller.close();
}
```

Output:

```text
Hello
World
```

---
## Real_Flutter_Example

Suppose a chat app. When a new message arrives:

```dart
controller.add(newMessage);
```

Our **`StremBuilder`** is listening. We don’t manually call **`setState()`** the **Stream** notifies the UI.

```text
New Message
     │
     ▼
StreamController
     │
     ▼
StreamBuilder
     │
     ▼
UI rebuilds
```

---
## Stream_vs_StreamController

Difference:

| **Stream** | **StreamController** |
| --- | --- |
| Read data | Produce data |
| Listen to events | Add events |
| Consumer | Producer |

---
## When_StreamController_will_be_used

Many libraries already provide streams for us like:

- **Firebase**
- **WebSockets**
- Bluetooth
- Sensors

We'll mostly write these rather than creating our own controller:

```dart
stream.listen(...)
// Or
StreamBuilder(...)
```

---
## Usage_of_Streams_in_Flutter

We'll encounter them in:

- **`StreamBuilder`**
- **Firebase Firestore** (`snapshots()`)
- **WebSockets**
- Bluetooth communication
- Location updates
- Audio/video playback events

---
## Final_Flow_of_Data

```text
Future  → One value → await

Stream  → Many values → listen()

StreamController → Produces events → Stream → StreamBuilder/UI
```
