**`switchMap()`** listens to a **`Stream<T>`**, and whenever a new value comes, it switches to a new inner stream and cancels the old one. Think of it like “Only care about the latest thing.”

To get this add **rxdart** package:

```yaml
dependencies:
  rxdart: ^0.27.7
```

Imagine this timeline:

- User A logs in → listen to A’s profile
- User logs out → stop listening to A
- User B logs in → listen to B’s profile

**`switchMap()`** automatically cancels the old stream and switches to the new one. If we didn’t use **`switchMap()`**, we could:

- leak listeners
- get wrong user data
- crash our logic

In one line, **`switchMap()`** transforms each emitted value into a new stream and automatically cancels the previous stream when a new value arrives.

**`_auth.authStateChanges()`** returns a **`Stream<User?>`** object and it emits whenever:

- user logs in
- user logs out
- app restarts and auth state is restored

**`switchMap((user) { ... })`** for each auth change, decide which stream to listen to next.

If user is logged out, we return a stream that emits **`null`**. NO database listening. But if user logged in, we switch to **Firestore** user profile stream

Mental model:

```text
Auth State Stream
       ↓
  switchMap
       ↓
 User Profile Stream (latest only)
```

```dart
Stream<AppUser> streamUserProfile(String uid) {
  return FirebaseFirestore.instance
      .collection('users')
      .doc(uid)
      .snapshots()
      .map((doc) => AppUser.fromMap(doc.data()!));
}
```

> **Note:** There’s also **`asyncMap()`** method too. Commonly used with **Firebase** auth
