Imagine this:

```dart
String userId = "u123";
String productId = "p456";
```

Both are just **String** so **Dart** allows:

```dart
fetchUser(String id) {…}
// call method to get user
fetchUser(productId); // logically wrong, need userId
```

Because compiler sees **`String`** == **`String`**. So, the traditional solution is a wrapper class (**`UserId`**) for type safety

```dart
class UserId {
  final String value;
  UserId(this.value);
}
fetchUser(UserId user) {…}
// call method to get user
fetchUser(UserId("u123")) // access using UserId.value
```

But every wrapper creates:

- Object allocation, memory overhead & extra boilerplate
- Problematic in large data systems and serialization-heavy apps

---
## Enter_Extension_Types

Using this we create:

- A new type wrapping existing representation
- With compile-time safety
- WITHOUT runtime object overhead

Wrapper class is like a real box around value while **`extension type`** is a compiler illusion over value. Mental Model:

**Wrapper class:**

- Extra runtime object

**extension type:**

- Compile-time abstraction only

Define types:

```dart
extension type UserId(String value) {}
extension type ProductId(String value) {}
void fetchUser(UserId id) {}
void fetchProduct(ProductId id) {}
// call method to get user
fetchUser(ProductId("p1")); // shows compiler error
```

---
## Important_Concept

**Concept-1**, At runtime **`UserId`** is basically represented as **`String`**, no extra wrapper object

**Concept-2**, It’s a “Zero Runtime Cost” Because compiler can optimize away abstraction. This concept is called “Zero-cost abstraction” which is very famous systems-programming idea in languages like:

- **Rust**
- **C++**
- **Swift**

Value this heavily. Now **Dart** is moving in this direction too.

**Concept-3**, **`extension`** keyword adds methods on already existing class so no new type is created while **`extension type`** creates entirely NEW TYPE

---
## Real_World_Use_Cases

This is where extension type shine:

- Ids like **`UserId`**, **`ProductId`** & **`OrderId`**
- Domain primitives like **`EmailAddress`**, **`PhoneNumber`** & Currency
- Security-sensitive values like **`HashedPassword`**, JWT Token and API key to avoid accidental misuse
- Backend engineering, very useful APIs, databases, DTOs and Clean Architecture
