So basically, **`main`** branch is the main app and if we want to add a new feature, we push it in a new branch and test it. **`main`** is usually the “stable” branch. In most projects, **`main`** (or sometimes **`master`**) represents the production-ready, stable code.

All features, bug fixes, or experiments happen in separate branches. Once tested and reviewed, the changes are merged into **`main`**. Here’s also comes the merge conflict and we need to resolve it.

**Pull Request** is a place to compare and discuss the differences introduced on a branch with reviews, comments, integrated tests and more. A **Pull Request** is **GitHub’s** way of saying: “I made changes in my branch, please review them and merge into another branch (usually **`main`**).” It’s not just about merging it’s a collaboration tool which lets others review our code.

PR review allows team members to:

- Comment on code lines
- Suggest changes
- Approve for merge

## Practice

Set up a local repo first and connect it with the remote repo. Add some files like **`hello.txt`** containing (“hello world”).

Create a new branch for a feature. Then, we’ll be in **`feat/login`** branch. Any changes here don’t affect **`main`**.

```bash
git switch -c feature/login
```

Make changes in the branch like add a **`hello.txt`** file containing (“login feature code”) & commit.

```bash
git add hello.txt
git commit -m "Add login feature"
```

Push branch to GitHub:

```bash
git push -u origin feature/login
```

Open a Pull Request (PR) on GitHub, Go to our repository on GitHub. We’ll see “Compare & pull request” for our branch → click it. Choose:

- Base branch: main
- Compare branch: feature/login
- Add title and description.
- Click Create Pull Request.

This allows code review, testing before merging.

**Merge the PR.** After reviewing, click Merge pull request.

Handle merge conflicts. Conflicts happen when two branches change the same line in a file. Like hello world, login feature code in text file. When we try to merge **`feat/login`** into **`main`**, Git will mark the conflict:

```text
<<<<<<< HEAD
Main branch change
=======
Login branch change
>>>>>>> feature/login
```

Just click on resolve conflict and clear out everything except the thing we want.

```text
Main branch change
Or
Login branch change
```

Then click mark as resolved. Done.

Choose Options:

- Create a merge commit → keeps all commits separate.
- Squash and merge → combine all commits into one.
- Rebase and merge → replay commits on top of main

After choosing hit merge and we can also add multiple comments for discussion.

After merging, delete the branch to keep repo clean

- Check out to **`main`** branch then

  ```bash
  git checkout main
  ```

- Delete from local

  ```bash
  git branch -d feature/login
  ```

- Delete from remote

  ```bash
  git push origin --delete feature/login
  ```

Finally update or **`git pull`** to update the project or **`main`**
