In **Git** and **GitHub**, **`origin`** typically refers to our personal fork of a repository (or the repository we cloned), while upstream refers to the original repository we forked from.

---
## Workflow_Context

When we fork a repository on GitHub, Git automatically sets up **`origin`** pointing to our fork. To keep our local copy in sync with the original project, we must manually add **`upstream`** using

```bash
git remote add upstream <url>.
```

Here:

- We fetch and merge changes from upstream to stay current.
- We push our branches to origin to share our work.
- We submit Pull Requests from your origin fork to the upstream repository.

---
## Key_Differences

| Concept | Origin | Upstream |
| --- | --- | --- |
| Belongs to | **You** (your personal fork) | **Original project** (source of truth) |
| Created when | Automatically when you **clone** | Manually added after cloning |
| Primary Use | **Pushing** your changes and opening PRs | **Pulling** latest updates and syncing |
| Typical URL | your-username/repo | original-owner/repo |
| **Write Access** | Yes (you can push directly) | No (usually read-only for contributors) |
