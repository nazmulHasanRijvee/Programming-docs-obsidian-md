## GitHub_Issues

Purpose: Track bugs, tasks, feature requests, or anything actionable in our project. Creating an Issue.

Go to our repo → Issues → New Issue. Fill in:

- Title: Short description
- Description: Detailed explanation, steps to reproduce (for bugs), or requirements (for features)

Example description for a feature:

```text
Title: Add login form
Description:
- Create a login form with email and password fields
- Validate input before submission
- Display error messages if credentials are wrong
- Style with project’s CSS
```

Assigning & Labeling Issues. Assign to ourself or team members → tracks responsibility. Labels categorize issues (bug, feature, enhancement, documentation, etc.)

```text
Assignee: @username
Labels: bug, help wanted, enhancement
```

Commenting & linking. We can comment with suggestions, updates, or questions. Reference commits or PRs using #:

```text
This fixes issue #12
```

Linking PRs automatically closes issues after merging if we write:

```text
Closes #12
```

## GitHub_Discussions

General conversation area for ideas, Q&A, and feedback. Less formal than issues, often used for brainstorming.

Example

```text
Title: Ideas for new authentication methods
Content:
- Maybe implement Google & GitHub OAuth
- Discuss pros and cons of JWT vs sessions
- Any thoughts on 2FA implementation?
```

## GitHub_Project_Boards

Purpose: Visual project management using Kanban-style boards. Creating a Project Board. Go to Projects → New Project. Choose a template: Kanban (To Do → In Progress → Done)

Columns

- To Do: Tasks that need to be done
- In Progress: Tasks currently being worked on
- Done: Completed tasks

Linking Issues & PRs

- Drag issues or PRs into the appropriate column
- Updates in issues/PRs automatically reflect on the board
