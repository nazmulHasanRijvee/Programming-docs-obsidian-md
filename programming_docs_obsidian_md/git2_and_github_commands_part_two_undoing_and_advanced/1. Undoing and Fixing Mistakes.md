
## git_reset_vs_git_revert

These both “undo” commits, but in different ways. Moves our branch pointer to a previous commit. Can modify history (dangerous if already pushed to remote).

**`git reset`**

---
## git_reset

Completely resets repo to that commit (erases later commits + changes). Use carefully, usually for local cleanup. We can get the commit hash from GitHub repo commits and copy that.

```bash
git reset --hard <commit_hash>
```

Discard all uncommitted changes

```bash
git reset --hard HEAD
```

Or, removes the latest commit and its changes. (This is destructive, be sure first)

```bash
git reset --hard HEAD~1
```

Keeps our changes staged (like “un-committing” but not deleting).

```bash
git reset --soft <commit_hash>
```

Undo the last commit (but keep changes). Use when the commit message or commit contents need fixing

```bash
git reset --soft HEAD~1
```

---
## git_revert

**`git revert`**. Safest way to undo on shared repos. Creates a new commit that “reverses” the changes from an old commit.

```bash
git revert <commit_hash>
git revert HEAD // or this
```

Example:

- Commit A pushed to GitHub: add login form
- Commit B pushed to GitHub: add bug 🐛
- git revert B → creates Commit C that undoes B (but keeps A).

History remains safe & clean.

---
## git_restore(new_command)

Introduced in newer Git versions as a replacement for git checkout (when used for files). Undo un-staged changes (reset file to last commit):

```bash
git restore file.txt
git restore . // to restore all tracked files
```

Undo staged changes (un-add file). Safer than juggling with git checkout + git reset.

```bash
git restore --staged file.txt
```

---
## git_stash

Temporarily save work without committing (e.g., switching branches quickly). Save changes:

```bash
git stash
```

List stashes. Used to view stashes. See all stashes stored in the box:

```bash
git stash list
```

Apply most recent stash:

```bash
git stash apply
```

Apply & remove:

```bash
git stash pop
```

Drop a stash:

```bash
git stash drop stash@{0}
```

Example workflow:

Editing code → need to pull new changes → stash → pull → apply stash back.

---
## git_reflog_(Recover_Deleted_Branches_&_Commits)

Even if we delete commits or branches, Git usually remembers them in its log. View reflog:

```bash
git reflog
```

Output example:

```text
a1b2c3d HEAD@{0}: commit: Fix bug
d4e5f6g HEAD@{1}: commit: Add feature
h7i8j9k HEAD@{2}: checkout: moving from main to feature
```

Restore branch:

```bash
git checkout -b recovered_branch <commit_hash>
```

Super useful if we accidentally delete a branch or reset too far.

## Quick_Cheatsheet

| Situation | Command |
| --- | --- |
| Undo last commit but keep changes | `git reset --soft HEAD~1` |
| Undo last commit & erase changes | `git reset --hard HEAD~1` |
| Undo safely (create new commit) | `git revert <commit_hash>` |
| Undo unstaged file changes | `git restore file.txt` |
| Undo staged changes (un-add) | `git restore --staged file.txt` |
| Temporarily save changes | `git stash` |
| See all stashes | `git stash list` |
| Recover deleted commit | `git reflog` + `git checkout -b newbranch <hash>` |
