**GitHub** branch protection rules are Repository settings that prevent direct or forced code pushes (**`git push --force`**) to critical branches like **`main`**

Ensuring all code changes are submitted via pull requests (PRs) and reviewed before merging with **`main`**. So, no one can edit or update **`main`** directly unless added in **Bypass List**

---
## Setup

Go to Repository in **GitHub** → Settings → Under Code & Automation Section → Rules → Rulesets → New Ruleset

Then set the name of the Ruleset. Select Enforcement Status to Active. Add branches in Target Branches (By default **`main`** is added) to specify which branches these rules apply

Then select Branch Rules and hit save.

---
## Bypass_List

Roles, teams, agents and users who are exempt from this Ruleset is specified here. So, these rules don’t apply to them. We can add:

- Deploy Keys
- Repository Admin (Select)
- Maintain
- Write
- Copilot code review
- Copilot cloud agent

---
## Branch_Rules

- **Restrict creations:** Prevents creating a branch with the protected name (**`main`**). Not Recommended.
- **Restrict updates:** Nobody can push directly to main unless they're on the bypass list. Recommended only if we always use Pull Requests
- **Restrict deletions:** Prevents deleting the **`main`** branch. Recommended
- **Require linear history:** Disallows merge commits. Only squash or rebase merges are allowed, keeping history clean.
- **Require deployments to succeed:** Deployment (e.g., Firebase Hosting) must succeed before merging. Recommended if we use PRs and CI
- **Require signed commits:** Every commit must have a verified GPG/SSH signature. Skip unless we specifically want signed commits
- **Require a pull request:** No direct pushes. Every change must go through a Pull Request.
- **Require status checks:** Ensures automated tests and CI (like **`flutter analyze`**, **`flutter test`**, **`flutter build`**) pass before merging.
- **Block force pushes:** Prevents **`git push --force`** to main. Highly Recommended
- **Require code scanning results:** Security scanning (e.g., **CodeQL**) must pass. Enable later if we add **CodeQL**
- **Require code quality results:** Blocks merges if code quality checks fail.
- **Restrict code coverage:** Requires minimum test coverage before merging. Skip until we have a solid test suite
- **Automatically request Copilot code review:** Copilot reviews every PR automatically. Only if we use GitHub Copilot
