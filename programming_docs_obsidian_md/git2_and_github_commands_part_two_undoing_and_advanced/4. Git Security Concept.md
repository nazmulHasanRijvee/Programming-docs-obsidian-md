When someone clones our public repository, they also get the **`.git`** file which is tracking the file changes. The **`.git`** contains:

- Commit History
- Branches
- Remote URLs
- Git metadata

It does not contain our GitHub password, OAuth tokens or SSH private keys. So, when they try to **`git push`** to that repo, **GitHub** will ask “who are you & do you have permission”. They will get an error like “Permission Denied”. Unless:

- We added them as collaborator
- Or they have stolen your credentials

---
## Getting_Local_Repository

If we lose our local repository we can just clone it again and Git will recreate the entire **`.git`** folder and working directory. Git itself doesn’t know if its us but **GitHub** authenticates us using:

- **HTTPS + Login:** GitHub may ask you to sign in
- **PAT (Personal Access Token):** A token stored in our credential manager
- **SSH (Recommended):** Git-Hub verifies our SSH key

Clone through SSH to get lost **`.git`** or local repo

## Mental_Model

Imagine:

```text
GitHub Repository
       │
       ├── You clone it
       │      └── .git folder created
       │
       └── Stranger clones it
              └── .git folder created
```

So, both have **`.git`** but when pushing the permission comes from **GitHub** authentication, not from the **`.git`** folder.

```text
Your SSH key      → Allowed
Stranger's key    → Rejected
```

## GitHub_Actions_Security

If we use **GitHub Actions** and if someone clones our public repo, they cannot see:

- Repository secrets
- Firebase deployment token stored as secrets
- API keys stored in GitHub secrets

Those remain on **GitHub**’s servers and are not included in the clone
