A good **GitHub** issue should answer:

> “What is wrong/needed → What exactly should change? → What are the acceptance criteria?”

---
## Recommended_Structure

The RECOMMENDED structure, we don't necessarily need every section for every issue:

```markdown
## Description

What needs to be changed and why?

## Current Behavior

What happens currently?

## Expected Behavior

What should happen after the change?

## Requirements

- [ ] ...
- [ ] ...
- [ ] ...

## Acceptance Criteria

- [ ] ...
- [ ] ...
- [ ] ...

## Technical Notes

Optional implementation details.

## Out of Scope

Optional things that should not be changed.
```

One distinction we should remember. Requirements = what needs to be built and Acceptance criteria = how we know we're finished.

---
## Real_Example

```markdown
## Description

Improve the UI/UX of the login and authentication flow to provide clearer
feedback, better visual hierarchy, and more consistent interactions across
authentication screens.

## Current Behavior

- Login form has inconsistent visual hierarchy.
- Validation and authentication errors are not presented consistently.
- Authentication actions do not provide sufficient loading feedback.
- Password visibility interaction can be improved.
- Auth-related screens do not consistently follow the application's design patterns.

## Expected Behavior

The authentication flow should provide a consistent, responsive, and
user-friendly experience with clear validation, loading, success, and error
states.

## Requirements

- [ ] Improve the login screen layout and visual hierarchy.
- [ ] Improve form validation and error messages.
- [ ] Add appropriate loading states during authentication requests.
- [ ] Improve password visibility toggle interaction.
- [ ] Apply consistent spacing, typography, colors, and component styles.
- [ ] Add appropriate transitions where they improve the user experience.
- [ ] Ensure authentication forms are accessible.
- [ ] Add a password strength indicator if required by the authentication flow.

## Acceptance Criteria

- [ ] Users can clearly identify required form fields.
- [ ] Invalid input displays a clear and actionable validation message.
- [ ] Authentication requests display an appropriate loading state.
- [ ] Authentication failures display a user-friendly error message.
- [ ] Password visibility can be toggled without losing the entered value.
- [ ] Login/signup screens follow the application's existing design system.
- [ ] Existing authentication functionality continues to work correctly.
- [ ] UI remains usable across supported screen sizes.

## Out of Scope

- Changes to authentication APIs.
- Changes to authentication business logic.
- Changes to backend validation rules.
- Changes to the authentication provider.

## References

- Figma/design: [Add link]
- Related issue: #[issue-number]
```
