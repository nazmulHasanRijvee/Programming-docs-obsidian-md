## Bugs
Everything is a **State machine**. Bugs are not random.  Every Bug is just an unexpected State. The program is always in some State:

- User logged in
- User logged out
- Loading, error and success

And Bugs happen when we end up in a State we didn’t plan for.

For, debugging instead of using console logs everywhere just map out the States:

- What States this thing can be in?
- Which transitions are possible?
- Where did we end up where we didn’t expect?

Always try to think in states

## Reduce_Code

Our code is a liability not an asset. More do not mean more value. Because every line of code we write we have to:

- Read
- Maintain
- Debug and Delete

More code = more bug possibilities. Don’t feel it’s a failure when we delete or reduce code on the other hand its productive. Before we write anything ask:

- Do we actually need this?
- Can we solve this with less?
- Can we delete something instead of adding?

## Think_in_Systems_Not_Components

Nothing in programming exist in isolation. Our function just doesn’t run it calls something and that calls other things. Find out how the functions are talking to each other (the Code Flow) and back-track them for debugging.
