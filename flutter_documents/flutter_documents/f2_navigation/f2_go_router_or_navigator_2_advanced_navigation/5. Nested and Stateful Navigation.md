Two mechanisms **`ShellRoute`** and **`StatefulShellRoute.indexedStack`** for nesting navigation inside a persistent UI shell (like a **`BottomNavBar()`** widget that stays visible while screens change underneath it):

- **`ShellRoute`** -> wraps child routes in a shared UI shell, backed by one additional **`Navigator`**
- **`StatefulShellRoute.indexedStack`** -> same shell concept, but gives each tab/branch its own independent **`Navigator`**, kept alive simultaneously via **`IndexedStack()`** widget

---
## Mental_Model

**`ShellRoute`** is one **`Navigator`** that gets overwritten; **`StatefulShellRoute`** is N `Navigator`s that all stay alive, with **`IndexedStack()`** just choosing which one is painted.

# Why_Needed

In a bottom-nav-bar app when the user taps from "Home" to "Settings" and back to "Home," they expect Home to be exactly where they left it (same scroll position, same unsaved form state). That's **persistent per-tab state**, and a single **`Navigator`** structurally cannot provide it

`StatefulShellRoute` solves this by giving each branch a **separate, real `Navigator`** that nothing destroys nothing when user switches away, tabs becomes a visibility toggle, not a rebuild.

---
## Basic_Usage

**`ShellRoute(builder:, routes:)`** -> a simple shell or  a single shared **`Navigator`** for all its children

**`StatefulShellRoute.indexedStack(builder:, branches:)`** -> Stateful shell where **`builder:`** gets a third argument, **`navigationShell`**

**`StatefulShellBranch(routes:)`** -> the currently active branch index

**`StatefulNavigationShell.currentIndex`** -> The currently active branch index

**`StatefulNavigationShell.goBranch(index, {initialLocation})`** -> Switches branches. This **is** the **`IndexedStack()`** body, passed to us to place in our UI

We're not building the **`IndexedStack()`** ourself. **`navigationShell`** is; we just place it where our content goes

```dart
final GoRouter _router = GoRouter(
  initialLocation: '/home',
  routes: [
    StatefulShellRoute.indexedStack(
      builder: (context, state, navigationShell) {
        return ScaffoldWithNavBar(navigationShell: navigationShell);
      },
      branches: [
        StatefulShellBranch(
          routes: [
            GoRoute(path: '/home', builder: (context, state) => const HomeScreen()),
          ],
        ),
        StatefulShellBranch(
          routes: [
            GoRoute(path: '/settings', builder: (context, state) => const SettingsScreen()),
          ],
        ),
      ],
    ),
  ],
);
```

In UI:

```dart
class ScaffoldWithNavBar extends StatelessWidget {
  const ScaffoldWithNavBar({super.key, required this.navigationShell});

  final StatefulNavigationShell navigationShell;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: navigationShell, // <-- this IS the IndexedStack of branch Navigators
      bottomNavigationBar: BottomNavigationBar(
        currentIndex: navigationShell.currentIndex,
        onTap: (index) => navigationShell.goBranch(index),
        items: const [
          BottomNavigationBarItem(icon: Icon(Icons.home), label: 'Home'),
          BottomNavigationBarItem(icon: Icon(Icons.settings), label: 'Settings'),
        ],
      ),
    );
  }
}
```

## Important_Concept

**`goBranch(index)`** alone preserves state by default. If the user had pushed a detail screen three levels deep on the Home tab, switching to Settings and back lands them exactly there, no extra code required.

But there's a UX gap this doesn't solve like re-tapping the currently active  tab does nothing by default. Most apps expect that to reset the tab to its root (the "tap Home again to scroll to top / pop back to root" convention). This needs an explicit check against **`currentIndex`**

**`initialLocation: true`** only when we're re-tapping the already-active branch otherwise we want state preserved, so it stays **`false`** for an actual tab switch.

```dart
void _onTap(BuildContext context, int index) {
  navigationShell.goBranch(
    index,
    initialLocation: index == navigationShell.currentIndex,
  );
}
```

## Industry_Practices

There are third-party packages like **bottom_shell_nav** built directly on top of **`StatefulShellRoute`**, adding production-grade extras like:
- Lazy branch loading (don't build a tab's widget tree until first visited)
- Scroll-to-top on re-tap, and adaptive layouts that switch from a bottom bar to a **`NavigationRail`** on larger screens.

**go_router_builder** now supports **`StatefulShellRoute`** with type-safe code-gen meaning SEE Module 10 will let us replace every raw path string in this module's code with a compile-time-checked route class.
