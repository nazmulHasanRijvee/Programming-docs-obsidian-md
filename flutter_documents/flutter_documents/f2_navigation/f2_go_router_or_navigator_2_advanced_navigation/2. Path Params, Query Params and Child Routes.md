Three ways data and hierarchy flow through our Route Tree (or between screens):

- **Path parameters** -> dynamic segments in the URL itself (`/users/:userId`)
- **Query parameters** -> the `?key=value` part of a URL, for optional/filterable state
- **Child routes** -> nesting a `GoRoute` inside another **`GoRoute's`** `routes:` list, which produces a  pushed screen automatically (Navigation Stack)

---

## Why_Use_It

- ##### Path_Param

	Static paths from [[1. GoRouter Foundations]] is fine for a home screen, but useless for a user profile, product page, where real DATA needs to be passed between screens

	Path params let one **`GoRoute()`** class serve infinite URLs (**`/users/1`**, **`/users/2`**, ...) instead of us hand-writing a route per ID

	To specify a path parameter, prefix a path segment with a **`:`** character, followed by a unique name, for example, **`:userId`**. 

- ##### Query_Param 

	Query params represent state (data) that should live in the URL, not in a widget field. Like a filter, a search term, a pagination page. If it's not in the URL, it's not shareable, bookmarkable, or restorable on refresh

	Used for passing big data as **Map** between screens

- ##### Child_routes
	For hierarchical or stacked navigation. Those aren't three unrelated screens, it's a drill-down. Nesting the route mirrors that mentally and gets us correct back-button behavior for free.

```text
Home → Family → Person
```

> NOTE: We can access the value of the Path & Query parameters by accessing them through the [GoRouterState](#Basic_Usage(GoRouterState)) object provided to the **`builder:`** or **`pageBuilder:`** callback in **`GoRoute()`** internally

## Mental_Model

```
URL:  /users/42?tab=posts
       │        │
       ▼        ▼
   path segment  query string
       │
       ▼
  matched against your route tree:
       GoRoute(path: '/users/:userId', ...)
                         │
                         ▼
           GoRouterState is populated with:
       ┌──────────────────────────────────────┐
       │ pathParameters: {'userId': '42'}     │
       │ uri.queryParameters: {'tab': 'posts'}│
       └──────────────────────────────────────┘
                         │
                         ▼
             passed into your builder: (context, state) => ...
```

For **child routes**, the tree structure is the navigation stack. A child route is not "a separate page," it's an implicit **`push()`**. We get the transition animation and in-app back button for free, purely from where we placed it in the tree.

```
GoRoute('/', routes: [ GoRoute('details') ])

Navigating to /details:
   Navigator stack:  [ HomeScreen, DetailsScreen ]
                        (base)     (pushed on top, back arrow appears automatically)
```

## Basic_Usage(GoRouterState)

**`GoRouterState`** has properties like:

- **`.pathParameters`** -> holds **`Map<String, String>`** of **`:name`** segments which is always a **String**
- **`.extra`** -> holds any non-URL-encodable object passed during navigation (covered module 3)
- **`.fullPath`** -> holds the route's full path template like **`users/:userId`**
- **`.matchedLocation`** -> the actual resolved URL that matched
- **`.name`** -> the route's **`name:`** if we gave it one (Module 4)

Here **`path: 'users/:userId'`** has no leading slash (**/**) on a child route. It's relative to its parent (`/`), so the full resolved path becomes `/users/:userId`

`state.uri.queryParameters['tab'] ?? 'overview'`  query params are optional by nature, so a fallback with `??`

```dart
final routerProvider = Provider<GoRouter>((ref) {
  return GoRouter(
    routes: [
      GoRoute(
        path: '/',
        builder: (context, state) => const HomeScreen(),
        routes: [
          // Child route nested under '/', becomes '/users/:userId'
          GoRoute(
            path: 'users/:userId',
            builder: (context, state) {
              final userId = state.pathParameters['userId']!;
              final tab = state.uri.queryParameters['tab'] ?? 'overview';
              return UserScreen(userId: userId, tab: tab);
            },
          ),
        ],
      ),
    ],
  );
});
```

## Important Concepts

Path params are never auto-typed. **`userId`** is a **`String`**, always. Even if our URL is `/users/42`. If our screen needs an `int`, we parse it (using **`int.tryParse()`**)

This is silently dangerous because **`context.go('/users/abc')`** compiles fine and only crashes at runtime with a `FormatException`.  Module 10 (`go_router_builder`)

```dart
final int? userId = int.tryParse(state.pathParameters['userId']!);
```

Child routes vs sibling top-level routes, functionally we could write **`/family-details`** as a flat top-level route instead of nesting **`details`** under **`/family`**. NOT RECOMMENDED, flat routing breaks correct backward navigation and makes the URL space unreadable at scale
