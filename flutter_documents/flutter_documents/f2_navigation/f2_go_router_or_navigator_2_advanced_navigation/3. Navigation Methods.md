**go_router** gives us four (**`go`**, **`push`**, **`pop`**, **`pushReplacement`**) distinct ways to move between screens, each with different stack semantics plus **`extra:`** parameter for passing non-URL-encodable data, and a **`Link()`** widget for proper web anchors

---
## Why_Use_It

URL is the source of truth, and `context.go()` re-derives the whole stack from it. But real apps need more nuance than that like:

- Switching bottom-nav tabs should replace, not pile up an infinite stack of tabs.
- Drilling into a detail screen should let the user come back which needs a proper push with a back button. (push and pop)
- A login → home transition should erase the login screen entirely and we never want back-button-to-login after authenticating. (push and replace)

One method (**`.go()`**) can't correctly express all three intents.

---
## Mental_Model

**`.go()`** operates on the whole location (declarative -> "be here now"), while **`push`**/**`pushReplacement`** operate on the Navigator stack directly (imperative ->"add/swap one entry").

```text
context.go('/products')
────────────────────────
  Rebuilds the ENTIRE stack to match '/products'.
  Before: [Login, Home, Cart]  →  After: [Products]
  Everything else is discarded.


context.push('/products/42')
────────────────────────
  Adds ONE screen on top. Stack grows.
  Before: [Products]  →  After: [Products, ProductDetail]
                                              ▲
                                    back button pops THIS only


context.pushReplacement('/home')
────────────────────────
  Swaps the TOP screen only. Stack length unchanged.
  Before: [Login]  →  After: [Home]
          (gone, unreachable via back button)
```

---
## The_Four_Navigation_Methods

| Method                             | Stack Effect                             | Returns         | Use When                                                        |
| ---------------------------------- | ---------------------------------------- | --------------- | --------------------------------------------------------------- |
| **`context.go(url)`**              | Replaces entire stack to match **`url`** | **`void`**      | Top-level navigation like tab switches, "go home"               |
| **`context.push(url)`**            | Pushes one screen on top                 | **`Future<T>`** | Drill-down, when user should be able to pop back                |
| **`context.pushReplacement(url)`** | Swaps current top screen only            | **`void`**      | Irreversible transitions like login → home, splash → onboarding |
| **`context.pop([result])`**        | Removes top screen                       | ---             | Returning from a **`push`**, optionally with a result value     |

## Basic_Usage

**`.push<T>()`** with a returned value. The pattern for "go pick something and come back with it":

- **`context.push<bool>(...)`** -> the generic `<bool>` tells `go_router` what type to expect back; `await` suspends it until the pushed screen pops.
- **`context.pop(true)`** -> the value passed to **`pop()`** is exactly what the **`await`** on the calling side receives.

```dart
// Screen A —> push and wait for a result
onTap: () async {
  final bool? confirmed = await context.push<bool>('/confirm-delete');
  if (confirmed == true) {
    // proceed with deletion
  }
},

// Screen B —> pop with a value
onTap: () => context.pop(true),
```

**`context.go()`** for tab switching. So, tabs don't stack infinitely:

```dart
BottomNavigationBar(
  onTap: (index) {
    switch (index) {
      case 0: context.go('/dashboard'); break;
      
      case 1: context.go('/settings'); break;
    }
  },
),
```

**`context.pushReplacement<T>()`** basically means push a new route while removing the current route from the stack.

Use it when the current screen should not be reachable by going back (Login → Home).

```dart
// Login Screen
onPressed: () {
  context.pushReplacement('/home');
},
```

## Important_Concepts

**`extra:`** parameter carries arbitrary **Dart** OOP objects that don't fit in a URL. **`extra:`** is held in memory, not encoded into the URL. That means browser refresh loses it, deep links can't carry it, and browser back/forward navigation can desync from it.

```dart
context.push('/checkout/confirm', extra: validatedAddress);

// In receiving side
builder: (context, state) {
  final address = state.extra! as Address;
  
  return ConfirmScreen(address: address);
},
```

**`Link()`** widget (from **url_launcher**) renders a real **`<a>`** tag on web. Meaning right-click → "open in new tab" actually works, unlike a **`GestureDetector()`** calling **`context.go()`**. Functionally identical to **`.go()`**, but semantically correct for web.

## Common_Mistakes

##### 1.Treating **`extra:`** as durable storage
If a screen reached via deep link or browser refresh depends on **`extra:`** being populated, it will be **`null`** and crash. Anything that must survive a refresh belongs in the URL (path/query param) or should be re-fetchable from an ID, not passed as an in-memory object.

##### 2. Mixing `Navigator` API with **`.go()`**
Use **`context.push()`**/**`context.pop()`** instead of calling **`Navigator.of(context).push`** directly, even though the raw `Navigator` API still technically works (but problematic).

##### 3. Using **`.push()`** for tab navigation
Every tab tap adds a new screen to the stack instead of replacing it. After a few taps, back button behavior becomes nonsensical and memory use climbs. Tab switches use **`.go()`**, not **`.push()`**
