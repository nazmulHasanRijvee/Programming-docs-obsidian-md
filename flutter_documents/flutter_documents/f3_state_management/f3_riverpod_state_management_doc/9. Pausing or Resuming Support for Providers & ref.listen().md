In **Riverpod 3.0**, **`ref.listen()`** listeners can be manually paused/resumed on demand using the **`ref.listenManual()`** API, `.pause()` and `.resume()` methods

Don’t forget to close it after work is done using `.close()`

```dart
final subscription = ref.listenManual(
  todoListProvider,
  (previous, next) {
    // Do something with the new value
  },
);
```

```dart
subscription.pause();
subscription.resume();
subscription.close();
```

---
## Pausing_Providers

At the same time, **Riverpod** now pauses providers in various situations:

- When a Provider is only used by paused Providers, it is paused
- When a Provider is rebuilds, all of its previous subscriptions (Providers that were read/watched) are paused until the rebuild completes. Instead of disposing them
- When a Provider is no-longer visible, it is paused too (Based off **`TickerMode()`**)

## For_Example

Consider an application with two routes:

- A **`HomePage`**, listening to a web-socket using a Provider
- A **`SettingsPage`**, which does not rely on that web-socket

Where user first opens the **`HomePage`** and then opens the **`SettingsPage`**. This means that while the **`SettingsPage`** is open, the **`HomePage`** is also open, but not visible

Then the web-socket Provider in the **`HomePage`** will be paused, possibly saving resources

**Riverpod** relies on **`TickerMode()`** to determine if a widget is visible or not. And when `false`, all listeners of a Consumer are paused. We can also use **`TickerMode()`** to manually control the pause behavior of our consumers

```dart

  @override

```

This improves performance and optimization of **Riverpod**
