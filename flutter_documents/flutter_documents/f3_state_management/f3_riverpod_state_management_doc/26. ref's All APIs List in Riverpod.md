Here:

- **`ref.watch(…)`:** Rebuilds UI, listens to changes and rebuilds widget when value (**`state`**) changes. Use it to display. UI watches **`state`** to rebuild not notifier make sure to have **`.watch(taskProvider)`** not **`taskProvider.notifier`**. We can also use **`ref.watch(provider.select((value) => value.name))`** see watch only one value part.

---
- **`ref.read(…):`** Call methods, changes **`state`** and trigger rebuild automatically. Use it to modify. Make sure to use **`.read(taskProvider.noitfier)`** for callbacks in notifier not **`taskProvider`**

---
- **`ref.listen(…):`** Side effects. Used instead of **`VoidCallback`**, **`ValueChanged<…>`** and **`T Function()`** name. See **`ref.listen`** in **Riverpod** part above. There’s **`ref.listenManual()`** too for pausing and resuming listeners

---
- **`ref.invalidate(…):`** Destroys current Provider instance along with its cached data, **`state`** and Notifier class and creates Provider instance again when **`ref.watch()`** happens again. Useful for **`AsyncNotifier<T>`**. See **`ref.invalidate`** and Manual Refresh method part above

---
- **`ref.invalidateSelf():`** Invalidates the current Provider itself, destroying its **`state`** and Notifier class. It will rebuild immediately if it still has listeners; otherwise, it rebuilds the next time it's watched (**`ref.watch`**). Useful for retry/reload logic from inside the Provider Notifier class. See **`ref.invalidate`** part above

---
- **`ref.keepAlive(…):`** After enabling Automatic Disposal, using **`ref.keepAlive(…)`** we can decide when the state or Provider stops being automatically disposed. Used when we want to keep the **`state`** of successful network requests, but not cache failed requests. Also, **`link.close()`** can be used to restore the auto-dispose behavior. See Auto Disposal in **Riverpod** part above

- **`ref.onCancel(() {})`:** Callback triggers when Auto disposal is enabled and **`Riverpod`** tracks whether a Provider (using **`ref.watch`**/**`ref.listen`**) has listeners or not. When that counter reaches zero, the Provider is considered “not used” (or calling **`ref.invalidate`** manually to destroy the Provider) then **`ref.onCancel()`** runs. See Auto Disposal in **Riverpod** part above

---
- **`ref.onResume(() {})`:** Called when a new listener (**`ref.watch/ref.listen`**) starts watching the Provider again before the Provider is disposed by Auto-Disposal. See Auto Disposal part above

---
- **`ref.onDispose(() {})`:** Callback runs when Provider is destroyed or disposed by Auto Disposal (or **`ref.invalidate`**). Flow, **`ref.onCancel()`** triggers and at that point, **Riverpod** waits for one frame (cf. await **`null`**) and after that Provider is still not used then the Provider is destroyed and **`ref.onDispose`** is triggered (used for disposing controllers). See **`ref.dispose(() {})`** in **Riverpod** part above

---
- **`ref.exists(…):`** Returns **`true`** if the specified Provider has already been initialized in the current **`ProviderContainer`**; otherwise **`false`**. Useful for checking whether a Provider has been created or not.

---
- **`ref.addListener(() {}):`** Registers a callback method (**`_onListen(…)`**) that's called whenever a listener (**`ref.watch/ref.listen`**) is added to the current Provider. Mostly used for advanced lifecycle tracking.

---
- **`ref.onRemoveListener(() {}):`** Registers a callback (**`_onListen(…)`**) that's called whenever a listener is removed from the current Provider. Mostly useful together with **`ref.addListener()`**.

---
- **`ref.refresh(…):`** Immediately destroys and recreates a Provider, returning its new value. Equivalent to **`ref.invalidate(provider)`** followed by **`ref.read(provider)`**.

---
- **`ref.isRefresh:`** **`true`** if the current build was triggered by a refresh (**`ref.refresh`**) rather than the initial build or a dependency change

---
- **`ref.isFirstBuild:`** **`true`** only during the Provider's very first **`build()`** run. Useful when initialization logic should run only once

---
- **`ref.isReload:`** **`true`** if the Provider is rebuilding because one of its watched dependencies changed (not because of a refresh).

---
- **`ref.mounted:`** Returns whether the Provider is still alive. Useful after **`await`** before updating **`state`** or continuing work

---
- **`ref.container:`** Gives access to the current **`ProviderContainer()`**, allowing interaction with other Providers at the container level. Mostly used for advanced use cases and testing.
