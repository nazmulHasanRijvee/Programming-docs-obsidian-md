**`ProviderContainer()`** is the **Riverpod**’s own unit testing tool which lets us read Providers, call Notifier methods and observe state changes with no Widget Tree involved We talk to the Notifier directly and test the leaf dependencies like repository layer and API caller

Instead of **`ref.read()`** we do **`container.read()`** and after the work is done, dispose the **`ProviderContainer()`** using **`.dispose()`** method. Also, override Providers using **`overrides: []`** property, to pass our created objects to implement those Providers (what they will return)


```dart
// ...
void main() {
  group('FavouriteSongsNotifier', () {
    late ProviderContainer container;

    setUp(() {
      container = ProviderContainer(
        retry: (_, _) => null,
        overrides: [
          …
        ],
      );
    });

    tearDown(() {
      container.dispose();
    });

    test('repository test', () {
      …
      final repo = container.read(songRepositoryProvider.future);
      // test repo...
    });

  }
```

There’s **`ProviderContainer.test()`** constructor that creates a new **`container`** and automatically disposes it after the test ends (no **`setUp()`** or **`tearDown()`** needed). See f9 testing and code quality directories f54 flutter testing doc for more info
