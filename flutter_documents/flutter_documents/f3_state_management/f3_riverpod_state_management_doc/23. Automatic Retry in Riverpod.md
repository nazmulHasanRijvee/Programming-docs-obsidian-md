## Automatic_Retry_in_Riverpod

Starting from **Riverpod** 3.0, Providers that fail during initialization (`build()`) will automatically retry. The retry is done with an exponential backoff and the Provider will be retried until succeeds or is disposed

The default behavior retries any error, and starts with a 200ms delay that doubles after each retry up to 6.4 seconds. This can be customized for all Providers globally using **`ProviderContainer()`**/**`ProviderScope()`**’s **`retry:`** parameter that takes a callback and internally gives us **`retryCount`** and the **`error`** (**`SocketException`**)

We can customize the retry logic, such as to skip specific errors or add limit to the number of retries or change the delay

```dart
void main() {
  runApp(
    ProviderScope(
      retry: (retryCount, error) {
        // Don’t retry any Provider for this error
        if (error is SomeSpecificError) return null;
        // Don’t retry more than 5 times
        if (retryCount > 5) return null;

        return Duration(seconds: retryCount * 2);
      },
      child: MyApp(),
    ),
  );
}
```

**`ProviderContainer()`**:

```dart
void main() {
  final container = ProviderContainer(
    retry: (retryCount, error) {
      if (error is SomeSpecificError) return null;
      if (retryCount > 5) return null;

      return Duration(seconds: retryCount * 2);
    …
}
```

Alternatively, this can be configured on Per-Provider basis by using the **`retry:`** parameter of the **Provider** constructor (**`NotifierProvider<….>`**, **`AsyncNotifierProvider<…>`** etc.)

```dart
final todoListProvider = NotifierProvider<TodoList, List<Todo>>(
  TodoList.new,
  retry: (retryCount, error) {
    if (error is SomeSpecificError) return null;
    if (retryCount > 5) return null;

    return Duration(seconds: retryCount * 2);
  },
);
```

> **NOTE:** See **Riverpod** code generation for the annotation’s version of this

## Disabling_Automatic_Retry

In general, this is a good thing as it makes our app more resilient to transient errors. However, we may want to disable/customize this behavior in some cases. To disable it just **return null** in the callback of **`retry:`** parameter

For Globally:

```dart
void main() {
  runApp(
    ProviderScope(
      // Never retry any provider
      retry: (retryCount, error) => null,
      child: MyApp(),
    ),
  );
}
```

**`ProviderContainer()`**:

```dart
void main() {
  final container = ProviderContainer(
    // Never retry any provider
    retry: (retryCount, error) => null,
  );
}
```

Alternatively, disable automatic retry on a per-provider basis using the `retry:` parameter of the Provider constructors (**`NotifierProvider<…>`**, **`AsyncNotifierProvider<…>`**)

```dart
final todoListProvider = NotifierProvider<TodoList, List<Todo>>(
  TodoList.new,
  // Never retry this specific provider
  retry: (retryCount, error) => null,
);
```
