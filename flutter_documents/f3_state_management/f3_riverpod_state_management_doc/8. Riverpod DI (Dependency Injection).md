#### Basic_DI:
\# If we want a data like **token** in our data layer (**ApiCaller**) which is coming from **Riverpod** we can’t access it without **ref** and normal classes like **ApiCaller** don’t have it this is where dependency injection comes in
 
\# In this approach now **ApiCaller** (Any normal class or data layer) is a **service** (Or use Repository-layer architecture) and other ones are **notifiers**

\# **Riverpod** declares dependencies up-front and inject them. This is the mental model for it:

```ASCII
UI
 ↓
StateNotifier / Notifier
 ↓
Repository / ApiCaller
 ↓
HTTP / DB
```

\# We need an **AuthModel** which will be the type of our notifier (**AuthNotifier**). This is going to give us the token using a getter method (Instead of using a getter we can directly access the token to like **ref.read(authNotifierProvider).token** but it’s not good architecture). Then we’ll create a **Provider** (**authProvider**) of this notifier (**AuthNotifier**)

\# We need a **Function() getToken** which will return a **String?** in **ApiCaller** class and will be initialized in the constructor. This is VERY important because of keeping **token** fresh/refresh otherwise **APICaller** will still hold old **token**

\# By using this when we call **getRequest** (http request) in **APICaller** it will call the **getToken** method every time, which will get the current **token** from auth notifier every time we send a request. This way no **ref** inside API.

\# Now we need **Riverpod** to create **ApiCaller** and inject dependencies so that **ApiCaller** has zero knowledge of **Riverpod**. Doing this by creating a Provider (**apiCallerProvider**) of **APICaller** and when returning we’ll inject the token using **authNotifier**’s getter(**accessToken**) and initialized in the constructor of **ApiCaller**

\# Now we’ll use it in a **StateNotifer** (**TaskNotifier**). Our notifier will take a **ApiCaller api** and initialize in the constructor (`TaskNotifier(this.api) : super(…)`). And when creating the Provider (**taskProvider**) of the notifier (**TaskNotifier**) it will take the **ApiCaller** class using its **apiCallerProvider** (Injected with token)

\# Then finally we can do what we want in UI using **taskProvider()** because everything is wired to it by **Riverpod**

\# Auth model or state:

```dart
class AuthModel {
  final String? token;
  // …
  const AuthModel({this.token, …});
}
```

\# Auth notifier (**SharedPreferences**):

```dart
class AuthNotifier extends StateNotifier<AuthModel> {
  AuthNotifier() : super(const AuthModel());
  String? get accessToken => state.token;
  // …
}
```

\# Auth Provider:

```dart
final authProvider =
	StateNotifierProvider<AuthNotifier, AuthModel>((ref) {
		return AuthNotifier();
});
```

\# **ApiCaller**:

```dart
class ApiCaller {
  ApiCaller(this.getToken);
  
  /// Function injection (important)
  final String? Function() getToken;
  
  // …
  headers: {
    'token': getToken() ?? '',
  },
  // …
```

 \# **Riverpod** DI (Dependency Injection). API caller provider:

```dart
final apiCallerProvider = Provider<ApiCaller>((ref) {
  final authNotifier = ref.read(authProvider.notifier);
  
  return ApiCaller(
    () => authNotifier.accessToken,
  );
});
```

\# Task notifier:

```dart
class TaskNotifier extends StateNotifier<TaskState> {
  TaskNotifier(this.api) : super(const TaskState());
  final ApiCaller api;

  Future<void> loadTasks() async {
    state = state.copyWith(apiState: ApiState.loading);
    final response = await api.getRequest(url: 'some-url');
    state = state.copyWith(apiState: ApiState.success);
  }
}
```

\# Task Provider:

```dart
final taskProvider = StateNotifierProvider<TaskNotifier, TaskState>((ref) {
  return TaskNotifier(
    ref.read(apiCallerProvider),
  );
});
```

> **NOTE:** We don’t need **get_it** here in this case because **Riverpod** already does the wiring by itself.

#### Alternative_DI_Approach:
\# Instead of injecting dependencies through the constructor of the classes in the `Provider<T>((ref) {…})` where **ref** is available

\# We can create a helper method like **getInstance(Ref ref)** that’ll take the **ref** as a parameter and inject the dependencies directly in the class and return the class instance or object we need in the `Provider<T>()`. No need to inject the dependencies through constructors

```dart
class DioClient {

  static Dio getInstance(Ref ref) {
    final dio = Dio(
      BaseOptions(…),
    );
    dio.interceptors.addAll([
      TokenManager(…),
      if (kDebugMode) LogInterceptor(requestBody: true, responseBody: true),
    ]);
    return dio;
  }
}

/// ref injected
final dioProvider = Provider<Dio>((ref) {
  return DioClient.getInstance(ref);
});
```

#### Dependency_Injection_in_Modern_Classes:
\# if we use `Notifier<T>`, `AsyncNotifier<T>`, `StreamNotifier<T>` (Modern) classes then we don’t need to manually wire anything in the Provider because **ref** is available in the **build()** method or any other manually defined method (**doThis()**) of those classes

\# We can access the singleton through the Provider using **ref.watch/read(apiServiceProvider)** (In **build** use **ref.watch**, in manual methods **doThis** use **ref.read**) directly in the Notifier class no constructor based dependency injection needed. Also define a getter method where **ref** will be available and use it in any class (Dependency Injected)

```dart
class AuthNotifier extends AsyncNotifier<List<Task>> {
  // Dependency injection
  APIService get apiService =>
      ref.read(apiServiceProvider);

  @override
  Future<List<Task> build() {
    // Or in here build, watch is needed here
    final apiService = ref.watch(apiServiceProvider);
    final response = await apiService.get(…);
    // …
    return taskList;
  }

  Future<void> addNewTask(Task newTask) async {
    /// Use read for manual methods, Dependency Injected
    final apiService = ref.read(apiServiceProvider);
    // Or use the getter method from above
    // …    await apiService.get(…);
    
    state = […state.value, newTask];
    // …
  }
```
