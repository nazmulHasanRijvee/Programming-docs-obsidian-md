#### Definition:
\# **Riverpod** is a State Management framework that:
- Fixes **Provider**’s architectural problem
- Removes **BuildContext** dependency
- Gives compile-time safety
- Works outside UI (API, services, background logic)
- Scales cleanly for large apps

\# Think of it as a global dependency and state container that is UI-agnostic. Mental model:

\# **Provider** (old mindset)

```
UI → context → provider → state
```

\# **Riverpod** (new mindset)

```
Provider → state
UI → watches provider
Services → read provider
```

\# State does NOT belong to widgets anymore. Widgets just observe **state**. So, **context** is not needed

---

#### Core-concepts:
\# **Riverpod** has only 3-core ideas, everything is built on this:

| **Concept**  | **Meaning**                        |
| ------------ | ---------------------------------- |
| **Provider** | A container for a value/state      |
| **ref**      | How you access other providers     |
| **Consumer** | A widget that listens to providers |

\# Just run this command in the terminal

```bash
flutter pub add flutter_riverpod
```

```YAML
dependencies:
  flutter_riverpod: ^3.1.0
```

\# Then import it

```dart
import 'package:riverpod/riverpod.dart';
```

#### Basic_Usage:
\# **ProviderScope** is ROOT of everything, this replaces **MultiProvider** we have to add this in the **main()** function. Without it **Riverpod** will not work. **ProviderScope** is like: “Enable **Riverpod** for the whole app”

```dart
…
runApp(
	ProviderScope(
		child: MyApp()
	)
);
```


\# **Riverpod** has different types of Providers for different problems:

##### 1. Provider (read-only values):
\# Use it when we need constants, services, repositories and API clients singleton pattern (alternative of **get_it** package). It has no state, no rebuilds. Example:

```dart
final apiServiceProvider = Provider<ApiService>((ref) {
	return ApiService();
});
```


##### 2. State Provider (simple mutable value):
\# Use it when we need to store one value (like `ValueNotifer<T>`), automatically notifies UI, counter app, selected index, toggle and small UI state. Do not use it for complex logic. Example:

```dart
final counterProvider = StateProvider<int>((ref) => 0);

ref.read(counterProvider.notifier).state++;
```


##### 3. StateNotifierProvider (Legacy or Deprecated use `Notifier<T>`):
\# Use it when we need complex logic, API calls, loading/error states and Complex UI
 
 \# First, we’ll create a **TaskState** model which will be the type of our `StateNotifier<T>`. We’ll have the states and the model containing the data here or the data directly. This is IMPORTANT if we don’t use this pattern, it will still work but the whole point of **Riverpod** will be meaningless like **.autoDispose**, lifecycle and lots of internal stuff won’t work. So, always keep the **state** (**ApiState.initial**) variables, model containing data here

**NOTE:**  We don’t need encapsulation in **Riverpod** because UI can’t modify a **state** (**TaskState**) data, the only way to change it is creating a new **state** and reassign it. Define a **copyWith(…)** method/manual setter to return the object with only modifying one or more properties (**taskState**, **error** and more) or  state (Or use helper methods like `TaskState loading () => TaskState(taskState: ApiState.isLoading)`) then assign it using `state = state.copyWith(…)` (Or helper methods) in notifier. In **.copyWith()**, method use **null** types and null safety **??** to make the parameters optional if the new passed parameter (**apiState**) in **copyWith** method is not **null** use it otherwise use the current existing property (**this.apiState**) model has now

```dart
class TaskState {
  final List<TaskModel> tasks;
  final ApiState taskState; // = ApiState.initial;
  final String? error;

  TaskState({
    this.tasks = const [],
    this.taskState = ApiState.initial,
    this.error,
  });

TaskSate copyWith ({List<TaskModel>? tasks, ApiState? apiState, String? error}) => TaskState(
      tasks: tasks ?? this.tasks
      taskState: apiState ?? this.apiState,
      error: error ?? this.error,
   );
}
```


\# **StateNotifier** (controller or logic holder). We can set an initial value/model here by using `class_name : super(value/model)`. We don’t need to call **notifyListeners()** here just have to assign it to **state** (It’s the initial value/model we have set before) and every time **state** is reassigned or changed it triggers rebuilt like **notifyListeners()**

```dart
class TaskNotifier extends StateNotifier<TaskState> {
  TaskNotifier() : super(TaskState());
  
  Future<void> loadTasks() async {
    state = state.copyWith(taskState: ApiState.isLoading);
    /// Or we can also directly assign the state using models Class name if we want
    /// state = TaskState.copyWith(…);
    final response = await ApiCaller.getRequest(url: Urls.newTaskURL);
    if (response.isSuccess) {
      state = state.copyWith(taskState: ApiState.success, tasks: response.body['data']);
      /// Or state = TaskState.copyWith(…);
    } else {
      state = state.copyWith(taskState: ApiState.error, error: response.errorMessage);
    }
  }
}
```


\# Finally, **Provider**. This is the **Riverpod** equivalent of **ChangeNotifierProvider** but safer. This is the value/model (**state**) our services and UI will listen to. We can also add  **StateNotifierProvider.autoDispose<…>(…)** to automatically clean memory which is perfect for bottom_nav, tabs and screens.

```dart
final taskProvider =
	StateNotifierProvider<TaskNotifier, TaskState>(
	  (ref) => TaskNotifier(),
);
```


\# Because of this approach we can create multiple and separate Provider’s for different items (**taskCards**) or share the same **Provider** globally which will be used in every where


##### 4. FutureProvider (async-only data):
\# Use it when one-time API call, no mutations and simple fetch. Here **Riverpod** handles loading, error and data automatically

```dart
final userProvider = FutureProvider<UserModel>((ref) async {
  return fetchUser();
});
```


##### 5. StreamProvider:
 Use it for WebSocket, **Firebase** and real-time data

> **NOTE:** There are updated modern classes Providers Like **NotifierProvider**, **AsyncNotifierProvider** and **StreamNotifierProvider** SEE them

#### UI_Listeners:
(**ref** APIs) UI listens to Providers using **extends ConsumerWidget** (most common). We can watch or read it using:

| **Method**           | **Purpose**                                                                                                                                                                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ref.watch()**      | rebuild UI, listens to changes and rebuilds widget when value changes. Use it to display. UI watches **state** to rebuild not notifier make sure to have **.watch(taskProvider)** not **taskProvider.notifier**. We can also use `ref.watch(provider.select((value) => value.name))` see [] |
| **ref.read()**       | call methods, changes **state** and trigger rebuild automatically. Use it to modify. Make sure to use **.read(taskProvider.noitfier)** for callbacks in notifier not **taskProvider**                                                                                                       |
| **ref.listen()**     | side effects. Used instead of **VoidCallback**, **ValueChanged<…>** and **T Function()** name                                                                                                                                                                                               |
| **ref.invalidate()** | Destroys current Provider instance along with its cached data, **state** and Notifier class and creates Provider instance again when **ref.watch()** happens again. Useful for `AsyncNotifier<T>`                                                                                           |

**NOTE:** For more list on **ref** APIs see below. Important APIs include:

- **ref.refresh(…)** (for **ref.invalidate** + **ref.read**)

- **ref.isFirstBuild()** (for initialization logic running only once)

- **ref.mouted** (after **await**) etc.

Remember **.read(taskProvider)** gives us the type (**TaskState** model) and **.read(taskProvider.notifier)** gives us the notifier class (**TaskNotifier**). Remember every time **state** is reassigned or changed it triggers rebuilt like **notifyListeners()**

#### Implementation_Example:
**main()** function. Best practice, wrapping **MyApp()** so we can use **Riverpod** (**ref.read / watch**) in **MyApp()**

```dart
void main() {
  runApp(
    const ProviderScope(
      child: MyApp(),
    ),
  );
} // Best Practice wrapping MyApp
```

Notifier and Provider. Remember every time we assign it to **state** (Which is the initial value/model we have set before using `: super(…)`) it does the work of **notifiyListeners()**, we don’t need it.

> **NOTE:** Getters in notifier for only **Providers** and DI (Dependency Injection) not UI don’t use getter for UI. UI should directly watch **state**

```dart
class TaskNotifier extends StateNotifier<TaskState> {
  TaskNotifier() : super(TaskState());
  
  Future<void> loadTasks() async {
    state = state.copyWith(taskState: ApiState.isLoading);
    /// Or we can also directly assign the state using models Class name if we want
    /// state = TaskState.copyWith(…);
    final response = await ApiCaller.getRequest(url: Urls.newTaskURL);
    if (response.isSuccess) {
      state = TaskState(taskState: ApiState.success, tasks: response.body['data']);
      /// Or state = TaskState.copyWith(…);
    } else {
      state = TaskState(taskState: ApiState.error, error: response.errorMessage);
      /// Or state = TaskState.copyWith(…);
    }
  }
}

final taskProvider =
    StateNotifierProvider<TaskNotifier, TaskState>(
  (ref) => TaskNotifier(),
);
```



In UI, **ConsumerWidget** (**WidgetRef Ref** is only available in **build()**). We can also consume the Provider using **ConsumerStatefulWidget** in this way we don’t need **WidgetRef ref** in **build()** method it becomes available globally cause **ref** is a property of **ConsumerState**. UI should watch **state** not rely on getters in notifiers:

```dart
class NewTaskScreen extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final state = ref.watch(taskProvider);
    if (state.taskSate == ApiState.isLoading) {
      return CircularProgressIndicator();
    }
    return ListView.builder(
      itemCount: state.tasks.length,
      itemBuilder: (context, index) => Text(state.tasks[index].title),
    );
  }
}
```
